## 0. WHAT THIS REGISTER MEANS BY "DRIFT"

**Drift** = a divergence between what SETURA's own governing artifacts say the
system *is*, and what the code and schema actually *are*. Drift is not the same as
a defect:

- A **defect** is behaviour that is wrong. Those live in
  `CROSS_PHASE_GAP_REGISTER.md`.
- **Drift** is a *description* that is wrong, a *contract* that has quietly moved,
  or a *structure* that has diverged from its stated design — regardless of whether
  anything currently misbehaves.

Drift matters independently of defects because drift is how defects survive. Every
P0 in the gap register sits downstream of a drift entry here: a document asserted
that something worked, so nobody checked it.

The governing artifacts treated as the drift baseline are:

| Artifact                              | Claimed authority                                    |
| ------------------------------------- | ---------------------------------------------------- |
| `ROADMAP.md`                          | Phase definitions, requirements, success criteria     |
| `ARCHITECTURE.md`                      | Frozen architecture (Phase 0.5 output)                |
| `supabase/migrations/01`–`49`          | The real schema and business logic                    |
| `supabase/functions/**`                | The real runtime surface                              |
| `docs/**`                              | Boundary and decision records                         |
| `PHASE_*` reports, `CROSS_CHECK_REPORT.md`, `AUDIT_REPORT.md` | Certification claims |

**Severity in this register** is the risk carried by the *divergence itself*, not
by the underlying defect (which is severity-rated in the gap register).

- **HIGH** — the drift actively causes wrong decisions by engineers, operators or
  buyers, or conceals a P0/P1.
- **MEDIUM** — the drift will cause wrong decisions once someone relies on the
  artifact.
- **LOW** — the drift is a factual inaccuracy with no current decision attached.
